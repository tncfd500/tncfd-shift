# 五大人員編制視覺化系統 - 線上多人共編架構評估與建議

## 一、 現況盲點與技術限制（為什麼不能只是把 HTML 傳上 GitHub？）
1. **靜態網頁（GitHub Pages）的限制**：
   - 目前的 HTML 採用瀏覽器的 `localStorage` 儲存修改內容。
   - 若僅僅將 HTML 檔案上傳到 GitHub Pages，使用者 A 在自己電腦上修改的資料**只會保存在 A 的電腦裡**。
   - 使用者 B 透過網址打開時，看到的仍然是原始檔案，無法取得 A 的修改；B 修改後 A 也看不到。
2. **資安與個資考量**：
   - 編制表內含五大隊 231 位同仁之真實姓名、職稱、分隊、公務電話與異動註記。
   - 若放在完全公開的網際網路上且不設任何防護，任何人（甚至網路爬蟲）都能存取並任意篡改或清空。

## 二、 三種推薦的具體建置方案

### 方案 A：Firebase 即時雲端同步 + 密碼鎖（最推薦）
- **運作架構**：
  - 網頁前端託管在現有的 GitHub Pages（`https://tncfd500.github.io/tncfd-shift/...`）或 Cloudflare Pages。
  - 後端串接免費的 Google Firebase Firestore 即時雲端資料庫。
- **優勢**：
  - **真正的多人即時共編**：同仁甲拖曳人員或改名字，同仁乙的螢幕幾毫秒內自動跳動同步更新。
  - **編輯密碼保護**：可設定一組通行密碼（例如 `5555` 或由您指定），只有知道密碼的同仁才能進入「編輯模式」進行拉動或修改，一般同仁只讀檢視，避免誤觸或外人惡意竄改。
  - **免架設伺服器**：完全由 Google 雲端託管，零主機維護成本。

### 方案 B：Google 試算表（Google Sheets）作為雲端資料庫
- **運作架構**：
  - 將人員編制存於 Google Drive 的 Google Sheet。
  - 網頁透過 Google Apps Script API 進行讀取與回寫。
- **優勢**：
  - 長官同仁習慣查看 Google 試算表，隨時有歷史版本記錄可回溯。
  - 權限可由 Google 帳號管理。
- **劣勢**：
  - Apps Script API 同步速度較 Firebase 慢 1-2 秒，且設定需要建立一個 Apps Script 專案。

### 方案 C：消防局內網 / 區域網路伺服器（LAN Server）
- **運作架構**：
  - 沿用目前專案既有的 `server.py` 架構，在隊部一台電腦執行 `start_lan.bat`。
  - 隊部或分隊同仁透過內部網路 IP（例如 `http://192.168.x.x:8765/`）連線共編。
- **優勢**：
  - **極致資安**：完全不出外網，外部無從攻擊或窺探。
- **劣勢**：
  - 只能在消防局內部網路連線，回家或在外手機若無 VPN 則無法連線。
