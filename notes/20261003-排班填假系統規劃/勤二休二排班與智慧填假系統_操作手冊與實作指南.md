# 臺南市政府消防局第五大隊 - 勤二休二排班與智慧填假系統：操作手冊與實作指南

本系統依據五大隊實際勤休規範、`1151003.ods` 與 `1150724115年五大隊輪休基準表.xlsx` 之底層公式重新工程化開發，建置為獨立、現代化且支援離線運行的互動式 Web 排班填假系統。

**系統執行檔路徑**：`C:\Users\TNCFD\Desktop\勤務系統\勤二休二排班與智慧填假系統.html`

## 📌 一、核心符號與業務規則定調

經排班負責人確認，本系統嚴格遵循以下底層定義：
1. **格子符號定義**：
   * `A`：**表定輪休**（勤二休二中休息的兩天）。
   * `[空白]`：**表定上班**（服勤日，統計上班人數時計算空白格數）。
   * `C`：**超勤加班補休**（在原本表定上班日申請核准）。
   * `G`：**加休**。
   * `休 / 公 / 婚 / 喪 / 事 / 病`：**其餘各項法定假別**。
2. **放假日判定**：
   * 整合行政院人事行政總處（DGPA）辦公日曆與內建休假日清單，所有週休二日、國定假日與補放連假自動塗滿**紅底白字**。
3. **在勤底限與安全官紅線**：
   * **幕僚最低在勤人數**：3 人（即每日「可填假人數」= 當日幕僚在勤人數 - 3）。
   * **安全官在勤紅線**：每日服勤人員中**必須至少保留 1 位合格安全官**（鄭國甫、曾志方、蔡宗憲、翁吉賢、謝振國）。若當日安全官人數為 0，系統即時亮起 `⚠️ 缺安全官` 紅色警報！

## 🚀 二、4 班勤二休二數學循環引擎

系統以 **民國 115 年 10 月 3 日** 為基準錨定點（Anchor Date）：
* **A 班**：10/3 為第二天上班 $\rightarrow$ 狀態為 `[空白]`（循環序列：`休 A、上 空、上 空、休 A`）
* **B 班**：10/3 為輪休第二天 $\rightarrow$ 狀態為 `A`（循環序列：`上 空、休 A、休 A、上 空`）
* **C 班**：10/3 為第一天上班 $\rightarrow$ 狀態為 `[空白]`（循環序列：`休 A、休 A、上 空、上 空`）
* **D 班**：10/3 為輪休第一天 $\rightarrow$ 狀態為 `A`（循環序列：`上 空、上 空、休 A、休 A`）

透過四態模數計算 $f(\Delta) = (\text{State}_{\text{anchor}} + \Delta) \pmod 4$，不論切換至哪一個年份或月份，全體 14 名同仁的勤二休二基礎輪休（A 與 空格）皆可 1 秒內自動鋪設完成。

## 🛠️ 三、主要功能操作教學

### 1. 選擇年月與重產基礎輪休
* 於上方工具列選擇欲編排之「年度」與「月份」。
* 點擊「🔄 重建全月基礎輪休 (A)」，系統即刻自動鋪滿全月表定班次。
* 工具列右側即時彙整當月「例假日天數」與「平常日天數」。

### 2. 點擊儲存格浮動選單填假（下拉選單與彩色快選）
* 點擊非「A」的上班日儲存格，立即彈出浮動選單，支援下拉選單選取或點擊彩色按鈕快選：  
  `[空白](上班) / 【C】超勤補休 / 【G】加休 / 【休】特休 / 【公】公假 / 【事】事假 / 【病】病假 / 【婚】婚假 / 【喪】喪假`。
* **表定輪休【A】防誤觸保護**：表定輪休【A】為系統自動排定，禁止直接修改或作為請假沖抵項目，點擊不彈出選單。
* **4 人底限授權鎖定**：若填假後全大隊當日上班人數低於 4 人，自動觸發安全鎖定，需輸入主管授權密碼 `501520` 始可破例放行。
* 狀態變更時，底部的「可填假人數」與「安全官在勤數」即時動態連動重算。

### 3. 雙層智慧排假仲裁（⚡ 雙層智慧排假，採用 S 型蛇行輪次演算法）
1. 點擊頂部「⚡ 雙層智慧排假」按鈕。
2. **第 1 層（管理者全局基礎排序）**：設定全體同仁之基礎排序（預設排序：`14, 11, 4, 7, 6, 10, 9, 13, 12, 5, 8, 2, 3, 1`）。
3. **第 2 層（同仁志願登記）**：選擇同仁、日期與欲申請假別（C/G/休/公...），點擊「加入志願」，系統依登記順序標註「志願 1、志願 2、志願 3...」。
4. 點擊「🚀 執行智慧仲裁排假」：
   * **S 型輪次分配**：
     * 第 1 輪（順向：首位 ➔ 末位）：依序審查各同仁之「第 1 志願」。
     * 第 2 輪（逆向：末位 ➔ 首位）：反向審查各同仁之「第 2 志願」。
     * 第 3 輪（順向：首位 ➔ 末位）：順向審查各同仁之「第 3 志願」。
     * 第 4 輪（逆向：末位 ➔ 首位）：反向審查各同仁之「第 4 志願」，依此類推。
   * **逐輪多重防呆檢核**：每筆志願皆即時檢驗「全大隊在勤 >= 4 人」、「幕僚在勤 >= 3 人」及「合格安全官在勤 >= 1 人」，核准後即時更新班表並輸出詳細成果報告。

### 4. 互調班精靈（🔁 互調班精靈）
1. 點擊「🔁 互調班精靈」按鈕。
2. 選擇「人員甲 + 日期 1」與「人員乙 + 日期 2」。
3. 預覽視窗即時顯示雙方狀態，並提示調班後之合法性。
4. 點擊「確認執行互調」，系統即自動完成兩者班別之對調互換。

### 5. 人員班別設定（👥 班別與人員設定）
* 可自由調整 14 位同仁的所屬班別（A/B/C/D 班）與是否具備安全官資格，調整後儲存即可重新套用。

### 6. 匯出 Excel (CSV) 與資料備份
* 點擊「📥 匯出 Excel (CSV)」可下載符合格式的班表檔案，直接使用 Excel 或 LibreOffice 開啟。
* 點擊「💾 備份資料」可下載 JSON 備份檔；若更換電腦點擊「📤 匯入備份」即可完整還原。
* 點擊「🖨️ 列印班表」即啟動專屬 A4 橫向列印最佳化版面。

## 📋 四、大隊排班表所有填假規範與圖例說明（完整法規與演算法規範）

本章節彙整大隊勤二休二排班系統之所有填假規範、圖例符號、勤務安全底限及 S 型蛇行輪次演算法，供排班承辦人與同仁查閱遵循：

### 1. 勤二休二基礎輪休與填假符號說明
* **勤二休二輪休制**：採 4 班循環（A/B/C/D 班），每位同仁整月表定約 15～16 天輪休【A】。
* **表定輪休【A】防誤觸保護**：
  * 格子標記為紅色粗體【A】者，為系統依輪休模數自動排定之「表定輪休」。
  * **禁止直接改假**：移至 A 儲存格時維持標準箭頭游標，點擊不會觸發任何下拉選單，防止誤觸或誤將請假沖抵表定輪休。
* **上班日填假方式（浮動選單）**：
  * 點擊非【A】之空白儲存格（表定上班日），立即彈出浮動選單，支援下拉選單挑選或彩色按鈕快選：
    * 🏢 `[空格]`：上班（表定服勤）
    * 🔵 `【C】`：超勤加班補休
    * 🟢 `【G】`：加休
    * 🟦 `【休】`：特休
    * 🟪 `【公】`：公假
    * 📙 `【事】`：事假
    * 🏥 `【病】`：病假
    * 💍 `【婚】`：婚假
    * 🖤 `【喪】`：喪假
  * **剔除 A 輪休防呆**：選單已全面剔除「A 輪休」選項，徹底杜絕邏輯衝突。
* **紅底白字日期**：自動依據行政院人事行政總處（DGPA）辦公日曆塗紅（含週休二日、國定假日與彈性連假）。

### 2. 勤務安全三大防線與主管授權防呆
* **第一道防線：全大隊最低 4 人在勤底限（密碼授權鎖定）**：
  * 每日全大隊上班人數底限為 **4 人**。
  * 若某日上班人數已降至 4 人，該日所有空白格自動進入安全鎖定。任何人員欲在該日請假，系統強制要求輸入大隊主管授權密碼 `501520`，密碼正確始可破例放行；取消或密碼錯誤則自動駁回。
* **第二道防線：大隊幕僚最低 3 人在勤底限**：
  * 每日大隊幕僚（座號 4～14 號）上班人數底限為 **3 人**。
  * 表格下方「可填假人數」即時運算公式：`可填假人數 = 幕僚在勤人數 - 3`。
* **第三道防線：合格安全官至少 1 人在勤覆蓋**：
  * 每日服勤名單中必須至少有 1 位合格安全官（曾志方、蔡宗憲、謝振國、鄭國甫、翁吉賢）在勤。
  * 若某日無任何合格安全官，系統即時亮起 `⚠️ 缺安全官` 紅色警報，並於仲裁及手動填假時予以阻擋。

### 3. 雙層智慧排假仲裁規範（S 型蛇行輪次演算法，Snake Draft）
* **演算法核心理念**：
  * 傳統單向排序容易造成優先權前段人員在多個志願中連續占滿熱門休假日。
  * 系統導入經典「S 型蛇行輪次輪替機制（Snake Draft Arbitration）」，兼顧排假最大公約數與志願先後權益。
* **S 型輪次審查流程**：
  * 同仁填報之請假志願依登記順序標註為「志願 1」、「志願 2」、「志願 3」...。
  * 🔹 **第 1 輪【順向】**：依管理者設定之全局基礎順序（例如 `14 ➔ 11 ➔ 4 ➔ ... ➔ 1`），由首位至末位依序審查各同仁之「第 1 志願」。
  * 🔹 **第 2 輪【逆向】**：將基礎順序完全反向（例如 `1 ➔ 3 ➔ 2 ➔ ... ➔ 14`），由末位至首位反向審查各同仁之「第 2 志願」。
  * 🔹 **第 3 輪【順向】**：由首位至末位，順向審查各同仁之「第 3 志願」。
  * 🔹 **第 4 輪【逆向】**：由末位至首位，反向審查各同仁之「第 4 志願」，依此類推。
* **動態輪數與安全驗證**：
  * 演算法輪數完全自適應，由登記志願數最多者動態決定，無寫死限制。
  * 每筆志願即時檢驗「原為 A 則略過」、「全大隊在勤 >= 4 人」、「幕僚在勤 >= 3 人」及「安全官在勤 >= 1 人」，核准即時寫入班表，並將結果分類顯示於成果視窗中。

### 4. 互調班精靈規範
* 支援同仁間「跨日兩日雙向互調（A 與 A 互調）」、「同日兩人對調」以及「同人跨日對調」。
* **雙向完整對調機制**：進行跨日互調時（例如甲 10/3 輪休 A 與乙 10/2 輪休 A 互調），系統會在 10/2 與 10/3 兩日同時將甲、乙的班別狀態交叉對調（甲在 10/3 變為上班、10/2 變為輪休 A；乙在 10/2 變為上班、10/3 變為輪休 A），確保兩人的勤休節奏與當日總人力完美守恆。
* **智慧門檻防呆**：若調班前每日在勤人力與安全官已符合門檻，互調班後保持人數守恆時不會誤跳密碼警報阻擋；僅於調班會導致單日上班人數低於 4 人或無安全官在勤時，方強制跳出主管授權密碼驗證。
* 執行完成後自動存檔、即時重新繪製網頁班表，並將對調細節記錄至操作紀錄中以供匯出 Excel 稽核。

### 5. 帳號登入與操作紀錄 Excel 匯出規範
* 支援 14 位同仁與管理者之快速下拉登入與帳號切換，亦提供訪客模式無障礙直接進入。
* 所有填改假別（含密碼破例授權紀錄）、調班、仲裁、匯出與列印動作皆即時記錄。
* 點擊「📊 匯出操作紀錄 (Excel)」即可下載包含「總表」與「每位同仁專屬工作表分頁」之標準 Excel 活頁簿（`.xls`）。

### 6. 大隊標準 ODS 匯出與 A4 單頁列印規格
* 點擊「📥 匯出 ODS」可直接產出符合大隊 `1151003.ods` 標準範本之試算表檔案。
* 點擊「🖨️ 列印班表」具備專屬 CSS 列印樣式，版面精準填滿 A4 橫向單頁（Page Count: 1），底部自動附上承辦人、審核、大隊長之官方簽章欄。

* **雙層智慧排假仲裁系統 S型蛇行輪次機制 (v1.0.14)**：
  * **S型輪次仲裁設計理念**：
    * 避免傳統單向優先排序導致排序前段同仁連續占滿多個志願額度，導入經典「S型蛇行順序輪替機制（Snake Draft Arbitration）」。
    * **第一輪（順向）**：由第 1 個到最後一個，依序審查各同仁之「第 1 志願」。
    * **第二輪（逆向）**：由最後一個到第 1 個，反向審查各同仁之「第 2 志願」。
    * **第三輪（順向）**：由第 1 個到最後一個，順向審查各同仁之「第 3 志願」。
    * **第四輪（逆向）**：由最後一個到第 1 個，反向審查各同仁之「第 4 志願」，依此類推直至全數審畢。
  * **多維度勤務安全防呆貫徹**：
    * 每一輪次皆即時檢驗「全大隊在勤 >= 4 人（低於 4 人觸發密碼鎖定駁回）」、「大隊幕僚在勤 >= 3 人」及「合格安全官在勤 >= 1 人」勤務門檻。
  * **視覺化輪次結果呈報**：
    * 仲裁結果清單依輪次（例如「第 1 輪（順向）」、「第 2 輪（逆向）」）分塊呈現，清楚標記每筆志願之審查順序、核准/駁回狀態與詳細原因，並自動同步至操作紀錄中。
* **互調班精靈跨日換休 A 邏輯修復 (v1.0.15)**：
  * **問題根本原因定位**：

### 7. 系統上線與多人協同架構規劃 (v1.0.16)
* **多人即時協同需求**：
  * 現行系統資料儲存於各瀏覽器之 `localStorage`。若僅上傳純靜態網頁，同仁操作將無法跨裝置互通。
  * 若要實現「給網址所有人都能連線操作且即時同步同一張班表」，必須串接中央即時資料庫（如 Google Firebase Firestore）。

  * ❌ **單純 GitHub Pages 不行**：GitHub Pages 為純靜態託管（Static-only），無伺服器與資料庫，若單純上傳，每位同仁依然「各看各的手機暫存」。
  * ✅ **GitHub Pages + Firebase 最佳實務**：前端靜態網頁放 GitHub Pages 產生網址，後端資料庫串接 Google Firebase Firestore 免費即時資料庫。甲同仁調班或填假，乙同仁的手機畫面會在 0.3 秒內自動同步！

  * 支援直接於介面貼入 Firebase Config 代碼，系統自動以 `onSnapshot` 監聽班表異動，並於操作時自動推播回寫。
