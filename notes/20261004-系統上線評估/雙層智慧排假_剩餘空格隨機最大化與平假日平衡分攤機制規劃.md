# 雙層智慧排假仲裁系統：剩餘可請假空格「隨機填假最大化與平衡分攤」規劃書

## 1. 核心需求與設計目標
在依據同仁「個人志願清單」與「S型輪次優先順序」完成第一階段智慧仲裁後：
1. **填假最大化**：若當月每日仍有「可填假空格」（即大隊幕僚在勤 > 3 人、安全官在勤 >= 1 人、全大隊在勤 > 4 人），系統主動將多餘空格分派給同仁填假，發揮休假最大效益。
2. **多維公平平衡**：
   - **總休假天數均衡**：確保全月每位同仁的總休假天數（A輪休 + C/G/其他假）差異最小化。
   - **假日 vs 平日比例均衡**：假日（週六、日及國定例假日）的補填假機會均等分配，避免特定人全佔平日或全分到假日。
   - **每人每月 3 天 G（加休）優先達標**：若同仁本月 G 假尚未排滿 3 天，補填時優先以【G】填補，直接滿足大隊加休規範。
3. **嚴格不踩紅線防呆**：
   - 不打破勤二休二核心輪休（A 不更動）。
   - 全大隊在勤人數嚴格維持 `>= 4` 人。
   - 大隊幕僚在勤人數嚴格維持 `>= 3` 人。
   - 安全官在勤人數嚴格維持 `>= 1` 人。
   - 不得破壞連續服勤上限與基本安全防線。

## 2. 演算法四階段規劃架構

```mermaid
flowchart TD
    A[第 1 階段：現有 S型志願仲裁] --> B[志願核准完畢，產生基準班表]
    B --> C{是否勾選「自動填滿多餘空格」?}
    C -- 否 --> End[維持志願排定成果]
    C -- 是 --> D[第 2 階段：加休 G 優先補齊]
    D --> E[走訪未滿 3 天 G 之同仁，在符合防呆之上班日補填 G]
    E --> F[第 3 階段：平假日多目標平衡隨機抽籤 (C/補休)]
    F --> G[計算各員目前：總休天數、假日休天數、平日休天數]
    G --> H[計算當月各日剩餘可請假名額配額]
    H --> I[先排假日餘額：指派給『假日休假數最少』且『可請假』之同仁]
    I --> J[再排平日餘額：指派給『總休假數最少』且『可請假』之同仁]
    J --> K[第 4 階段：防呆覆核與成果報告]
    K --> L[更新班表、寫入操作紀錄、呈顯最大化分攤成效統計]
```

### 階段一：保留既有志願（S型輪次）
完全尊重同仁主動登記的志願，優先核定第 1、2、3 志願。

### 階段二：法規 G 假優先補足（每人 3 天）
- 計算各員當前 G 天數。
- 若有同仁未滿 3 天，優先在其表定上班日（空白處），於符合 4 人與安全官的前提下隨機補填【G】，直到全體同仁皆滿 3 天 G。

### 階段三：多餘名額隨機公平分配（平衡平日與假日）
1. **分日分流**：將月份中仍有配額的日期分為「例假日組」與「平日組」。
2. **假日優先公平分配**：
   - 走訪尚有餘額之「例假日」。
   - 候選人池：當天表定上班、且當天請假不會違規的同仁。
   - **權重評分機制**：優先挑選「目前已排假日休假天數最少」的同仁；若多人相同，則「隨機（Random Shuffle）」抽出 1 人，填入【C】（超勤補休）。
3. **平日餘額填滿**：
   - 走訪尚有餘額之「平常日」。
   - **權重評分機制**：優先挑選「本月總休假天數最少」的同仁；若多人相同，則「隨機」抽籤填入【C】。
4. **動態更新配額**：每補填 1 人，即時更新該同仁的休假積分與當日剩餘名額，重複循環直到全月所有工作日皆達最低門檻（或所有人無法再排）。

## 3. UI 介面設計規劃
在「⚡ 雙層智慧排假仲裁系統」彈出視窗中新增：
1. **功能切換核取方塊**：
   - `[☑] 仲裁後自動填滿剩餘可請假空格（最大化公平分攤）`
2. **預設假別選擇**：
   - 剩餘名額補填假別：預設【C 超勤加班補休】（未滿 3 天 G 者自動先補【G】）。
3. **成效報告面板**：
   - 執行後顯示：
     - 志願核准天數：XX 天
     - 系統自動補足 G 假：XX 天
     - 系統隨機最大化補假：XX 天
     - 各員最終「平日休 / 假日休 / 總休天數」分佈對照表（證明公平性標準差最小）。

## 4. 效益評估
1. **零爭議性**：志願第一、規則第二、剩餘隨機且平衡，無人為偏袒。
2. **合規保證**：順帶徹底解決「每人每月必須 3 天 G」的缺額問題。
3. **極致休假福利**：在不違反最低 4 人安全底線的前提下，將可休假名額用好用滿。
