# 勤二休二排班與智慧填假系統 — 多人線上協同部署評估報告與架構方案

## 一、批判性顧問核心評估

若單純將現有的 `勤二休二排班與智慧填假系統.html` 上傳至靜態網頁空間（如 Cloudflare Pages、GitHub Pages 等），**只能讓大家各自「看到」網頁，但無法達到「大家共同編輯同一張班表」的效果**。

### 為什麼純靜態上線不行？
1. **資料孤島**：現有系統的班表與登入紀錄全部存放在同仁手機或電腦瀏覽器的 `localStorage` 中。A 同仁填假或調班，只存在 A 同仁的手機內，B 同仁完全看不到。
2. **覆蓋與衝突**：多人同時操作時，若無中央即時資料庫（Realtime Database 或 Firestore），會產生嚴重的版本衝突與排假撞期。
3. **資訊安全與機敏考量**：消防大隊人員姓名、假別與主管密碼（`501520`）若放在公開網頁前端，任何知道網址的人按 F12 就能看到主管密碼。

## 二、推薦的上線架構方案

### 方案 A：Firebase + Cloudflare Pages / Workers（最推薦，免費且多人即時同步）
* **資料同步**：串接 Google Firebase Firestore，當甲同仁劃假或調班，乙同仁的手機畫面會在 0.5 秒內自動跳轉更新。
* **網頁發布**：前端部署至 Cloudflare Pages，具備全球 CDN、高速且永久免費，並可綁定自訂網址或大隊網域名稱。
* **主管安全**：授權密碼與後台核准改為雲端驗證，保障同仁名冊與勤休隱私。

### 方案 B：機關內部伺服器 / 內網 NAS Web Server（高度機敏推薦）
* 部署於消防局內部伺服器或局內封閉網路，僅限公務電腦或專屬 VPN 登入。
* 資料庫使用輕量 SQLite 或 PostgreSQL，由專人集中管理與備份。

### 方案 C：Google 試算表（Apps Script Web App）輕量版
* 將後端改為 Google Sheets API，同仁操作網頁時自動寫入雲端 Google 試算表。
* 優點是長官可直接在 Google Drive 查閱 Excel/Sheet，缺點是並行大量點擊時反應稍慢。
